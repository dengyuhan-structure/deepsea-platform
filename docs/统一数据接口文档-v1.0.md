### 1.1 第 5 条为什么砍（唯一一条覆盖了组员答复的决定）

| 理由 | 说明 |

| **工作量硬约束** | 《任务拆解》算过：初版需 **≈70 人日**，两周可用**约 30 人日**，缺口一倍多 |

### 1.2 第 9 条为什么"扩"而不是"砍"

不扩模拟器 → 结构安全的锚泊张力、网衣监测、结构形变、能源保障**四块全部禁用灰显** → 10-16 初版只剩"灾害分级预警"一块能演示；
且**模拟器同时是全项目唯一的造故障工具提供方**，断它会连带断掉整个闭环证据链。

> ⚠️ **一处尚未裁定的冲突**：第 9 条把**数据源备齐了**（2 人日），但《任务拆解》第十二节建议把"网衣监测 / 结构形变 / 能源保障"三个模块**砍掉**。

### 2.1 🆕 为什么加 `source_detail`（v1.3）

王浩然在《鱼类板块》里要求明细表标注两种来源：**「模拟养殖历史数据」** 和 **「AI 视觉实时仿真数据」**。

但 `source` 是**冻结的 4 值枚举**（仿真 / 公开 / 实测 / 演示），**不能改**（零号纪律：冻结字段不许改名，只许加字段）。

**所以：`source` 保持不变，细节放进新字段 `source_detail`。**

| 界面怎么显示 | 说明 |
|---|---|
| 标签主体 | 显示 `source` 的中文（仿真数据 / 公开数据 / 实测数据 / 演示数据） |
| 鼠标悬停 | 显示 `source_detail` 原文（如「TFBID 公开数据集」「模拟养殖历史数据」） |

> **同一件事不许起两个名字** —— 加一个"更细的说明"，而不是把枚举撑大。

### 2.2 🆕 为什么 `risk_flag` 标"派生"

王浩然要求明细表有「数据质量 / 风险等级」列（正常 / 注意 / 风险），且**与时序图红点对应**。

**但它不是独立采集的数据**，而是从"这一行有没有命中规则"推出来的：

| `risk_flag` | 判据 |
|---|---|
| `normal` 正常 | 该行没有命中任何规则 |
| `notice` 注意 | 命中了**蓝色或黄色**规则 |
| `risk` 风险 | 命中了**橙色或红色**规则 |

> ⚠️ **它和 `quality` 不是一回事**：`quality` 说的是"**这个数可不可信**"（好 / 超时 / 疑似异常），
> `risk_flag` 说的是"**这个数危不危险**"。**两个都要有，不许合并。**
>
> ⚠️ 也**不许**和 `risk_level`（告警等级 blue/yellow/orange/red）混用 —— `risk_level` 挂在**告警事件**上，
> `risk_flag` 挂在**数据行**上。粒度不同。

> ✅ **2026-10-05 裁定（N3，刘桐麟拍板）**：
>
> **① 单位定死**：`pv_energy_today`（发电**量**）与 `battery_energy`（储能**电量**）**是能量 → `kWh`**；
> 而 `pv_power`（发电**功率**）与 `total_power`（**功率**）**是功率 → `kW`**。

> **② 补一个字段 `battery_capacity_kwh`**（这是本次发现的缺口）：

> 补上之后三者的关系是：
>
> ```
> battery_energy = battery_soc / 100 × battery_capacity_kwh
> ```
>
> **有容量的好处**：能源保障页能显示"**还剩 42 kWh**"，而不是只有"剩 68%" —— 后者说不出还剩多少电。

>
> **为什么不给它 lux**（这是本次唯一一处推翻了组员原始写法的裁定，理由要说清）：

| 对比项 | `light_intensity` | `light_dimming_pct` |
|---|---|---|
| 是什么 | **环境里测到的光**（自然光 + 补光的合成） | **灯具自己的出力档位** |
| 谁提供 | 环境（刘伟豪） | 智能（李志成，设备模拟器上报） |
| 决策链位置 | **决策的输入**（和 `target_light_lux` 比，决定开不开灯） | **执行的结果**（灯到底开到几档） |

> **若给它 lux，会出三个麻烦**：
> ① 智能补光页要**并排显示两个 lux**，值班人分不清哪个是哪个，**得靠小字解释**——名字没取好才需要解释；
> ② **同一束光从两个地方报**（灯一开 `light_intensity` 本来就会涨），将来对不上就会互相打架——*"灯说它开了，环境光没变亮，谁错？"*，而**"不允许静默失败"是本项目的立身之本**，多一条可能自相矛盾的数据源是净负债；
> ③ **决策输入与执行结果同单位**，代码里最容易拿错变量，且**拿错了不报错、只是数不对**。
>
> **改名理由**：字段是当天新增、尚无人实现，**现在改名几乎零成本**；`light_dimming_pct` 让单位写在名字里，永久无歧义（合规范 1.1"单位直接进字段名"）。

### 8.1.2 ⚠️ 一个必须知道的客观限制：**东亚/西太平洋没有可用的 NDBC 站**

| 区域 | 站点 | 实测结果 |
|---|---|---|
| 黄海 / 东海 / 朝鲜海峡 | `22101`~`22108`（韩国气象厅浮标，托管在 NDBC） | ❌ **只有 `.drift` 漂流数据**，无 `realtime2` 气象文件 |
| 帕劳 / 密克罗尼西亚 / 马绍尔群岛 | `52201` `52212` `52213` `52214` `52216` | ❌ **只报气温**，风速/水温/浪高全为 `MM`（实测 1975 行中 0 行有风速） |
| 日本近海 DART 浮标 | `21413` `21418` `21420` | ❌ `met=n`，只有海啸监测数据 |

**结论**：**NDBC 上能取到的环境数据全部来自美国管辖海域的浮标。**
这不是我们挑得不好，是**数据源本身的覆盖限制** —— 公开、可实时更新、格式规范的浮标数据，
目前只有 NOAA NDBC 这一家能免登录取到（国内海洋数据中心需申请或登录）。

> ✅ **可以这么说**："环境数据采用 NOAA NDBC 公开浮标实时数据，**公开可查证、可复现**。
> 我们排查过东亚与西太平洋的可用浮标，NDBC 在该区域没有提供气象数据，因此选取了
> **覆盖不同海况类型**的三个站点作为开阔海域环境参考。"
> ❌ **不许这么说**："这是我国某养殖海域的实测数据。"

|---|---|
| 环境数据来源**真实**（NDBC 公开浮标） | 说成"**真实养殖基地**数据" |
| 场景是**模拟**的深远海养殖站点 | 说成"我们对接了某养殖企业" |
| 数据来源在界面上**逐一标注** | 把仿真数据说成真实数据 |

> **数据来源真实是加分项，场景不要说成真实养殖基地。** 主动标出来源反而是加分项——
> **用假数据装成真的，才是答辩时最容易被戳穿的事。**

### 8.3 数据来源标注话术（全项目统一）

> **"平台数据通过标准接口接入，演示环境用仿真数据和公开数据，接口已留好，随时能接真实数据。"**

## 九、指令接口（三条 · ✅ 本文件定稿）

| 接口 | 方向 | 传什么 | 谁提供 |
|---|---|---|---|
| **下发指令** | 后台 → 接入层 | `command_id` `device_id` `command_type` 参数 `timeout_ms` | 李志成 |
| **查询指令执行结果** | 任意板块 → 智能 | `command_id` → `command_status` `receipt_result` `retry_count` | 李志成 |
| **查询设备实时状态** | 任意板块 → 智能 | `device_id` → `device_online` `device_state` `device_params` | 李志成 |

```json
// 下发指令（示例）
{
  "command_id": "cmd_20261005_0001",
  "device_id": "feeder_01",
  "command_type": "feed",
  "params": { "amount_kg": 12.5 },
  "timeout_ms": 5000,
  "ts": 1758969600000
}
```

```json
// 返回回执（示例）
{
  "command_id": "cmd_20261005_0001",
  "success": true,
  "result": "executed",
  "actual_ts": 1758969604200,
  "error_code": null
}
```

```json
// 出错返回（统一格式）
{ "code": 503, "msg": "设备离线" }
```

| code | 含义 | 什么时候用 |
|---|---|---|
| `200` | 正常 | — |
| `400` | 参数错误 | 字段缺失、类型不对、超时时间非法 |
| `404` | 对象不存在 | 设备号 / 站点号查不到 |
| `503` | 设备离线 | 命令发不下去、取不到数据 |
| `504` | 数据超时未更新 | 接口连得上，但数据是旧的 |
