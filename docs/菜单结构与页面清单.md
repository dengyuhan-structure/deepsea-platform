## 三之二、🔴 2026-10-06 新增：管理板块（4 页）

> 这一节是本日新增，**与上面"合计 11 页 / 24 页"的口径并存**：原 24 页规划不变，
> 管理板块是**新增的第 7 个一级板块**，总页面数由 24 变为 **28**（已建 17）。

```
└── 管理                      ← 场长 / 运维（4 页）
    ├── 网箱与站点          ← 这个网箱养什么鱼
    ├── 鱼种档案            ← 30 个种的温度参数 + 体长体重参数，带出处
    ├── 存箱量台账          ← 放养/分箱/死淘/起捕流水
    └── 标定与维护          ← 设备台账 + 计量标定状态
```

### 为什么单开一个板块（而不是塞进"跨板块"）

| | 跨板块 · 参数配置 | 管理板块 |
|---|---|---|
| 视角 | **技术参数**（阈值、规则） | **生产经营**（哪个网箱养什么、放了多少） |
| 谁用 | 工程师 / 运维 | **场长 / 值班长** |
| 变化频率 | 很少改 | **每批鱼都变** |

**"网箱养什么鱼"是生产事实，不是技术参数** —— 归属必须分清。

### 这一板块解决的根因问题

平台原来把「养什么鱼」写死在代码里，参数散落各处。
实测踩过两次：后端硬编码体长体重参数 `0.0218/3.02`；水温阈值写死 `20.5℃`
（**导致大黄鱼在长得最好的时候被报警**）。

现在以 `data/farm.json` 为**单一事实来源**：

```
farm.json 说 "cage_01 养大黄鱼"
   ├─→ 水温告警线 25.5 / 28.0 ℃          （自动）
   ├─→ 体长体重参数 a=0.0195  b=2.9775   （自动）
   ├─→ 起捕规格、养殖周期                 （自动）
   └─→ 存箱量由台账算出                   （自动）
```

**改一处，全平台跟着变。** 演示路径：管理 → 网箱与站点 → 改鱼种 → 水温阈值立刻从 28℃ 变成新品种的值。

### ⚠️ 与原规划的冲突已核对

- `智能 → 设备状态`、`智能 → 指令日志` **已有归属**，管理板块**不重复建**这两项
- 管理板块的「标定与维护」管的是**计量标定**，与「设备状态」管的是**在线与否**是两件事

## 四、统一布局（所有人照这个填）

```
┌────────────────────────────────────────────────────────────────┐
│ ① 顶部横条                                                      │
│   平台名 │ [总览][鱼类][环境][结构安全][智能] │ 数据来源标签      │
├──────────────┬─────────────────────────────────────────────────┤
│ ② 左侧竖直菜单│  ③ 主内容区                                      │
│   当前板块的  │     ┌─ 数值卡区（可选）─────────────────┐        │
│   小板块列表  │     │ ┌────┐ ┌────┐ ┌────┐              │        │
│              │     │ │指标│ │指标│ │指标│              │        │
│  · 页面 1     │     │ └────┘ └────┘ └────┘              │        │
│  · 页面 2     │     └──────────────────────────────────┘        │
│  · 页面 3     │     ┌─ 主图区 ────────┐ ┌─ 侧栏（可选）────┐    │
│              │     │ 曲线 / 热力图    │ │ 事件列表 / 详情  │    │
│              │     └─────────────────┘ └─────────────────┘    │
│              │     ④ 操作条：[时间窗切换] [手动触发]            │
└──────────────┴─────────────────────────────────────────────────┘
```

**四个区域的职责**：

| 区域 | 放什么 | 谁改 |
|---|---|---|
| ① 顶部横条 | 平台名、大板块切换、**数据来源标签** | 刘桐麟维护，别人不要改 |
| ② 左侧菜单 | 当前板块的小板块列表 | 刘桐麟维护 |
| ③ 主内容区 | 各人自己页面的内容 | **各板块自己写** |
| ④ 操作条 | 时间窗切换、手动触发按钮 | 各板块自己写 |

## 六、你那个板块的页面该怎么摆（逐板块建议）

### 刘伟豪 · 环境（2 页）

| 页面 | 数值卡区 | 主图区 | 操作条 |
|---|---|---|---|
| 海况 | 浪高 (m)、风速 (m/s)、气温 (℃) | 浪高+风速双曲线 | 时间窗切换 |
| 水质 | 水温 (℃)、溶氧 (mg/L)、盐度 (‰)、pH | 多参数曲线（可勾选显示） | 时间窗切换 |

> 提醒：**单位必须显示在数值卡上**。水温是 ℃，盐度是 ‰ 还是 PSU 要一次定死，写错一次三个板块一起错。

### 邓宇涵 · 结构安全（2 页）

| 页面 | 数值卡区 | 主图区 | 操作条 |
|---|---|---|---|
| 灾害预警 | 当前最高预警等级、活跃预警数 | 分级预警列表（等级色阶）+ 触发指标 | "查看触发依据"按钮 |
| 能源保障 | 按你定案后的方案填 | 按你定案后的方案填 | — |

> **灾害预警页的关键**：每条预警必须能点开看到"哪条数据触发的、命中了哪条规则"。这是答辩必答题。

### 李志成 · 智能（2 页）

| 页面 | 数值卡区 | 主图区 | 操作条 |
|---|---|---|---|
| 自动投喂 | 当前生物量、上次投喂量、投喂机状态 | 投喂记录时间线 + 命令状态机进度条 | "下发投喂命令"按钮 + 确认弹窗 |
| 智能补光 | 当前光照、灯具状态、补光依据 | 光照曲线 + 补光记录 | "下发补光命令"按钮 + 确认弹窗 |

> **命令状态机要显示在页面上**：已创建 → 已发出 → 已收到回执 → 成功（或 超时 → 重试中 → 失败 → 升级报警）。这一条答辩直接展示，很有说服力。
