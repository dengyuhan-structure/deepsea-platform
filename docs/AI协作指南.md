## 2. 你的边界（🔴 最重要的一节）

### ✅ 你能改的

| 文件 | 说明 |
|---|---|
| `frontend/pages/<你的板块>.js` | **你的主战场**。一人一个文件，别人不会碰 |
| `backend/api/<你的板块>.py` | 需要新接口时加在这里 |

> 路径里的 `<你的板块>` 是 `fish` / `env` / `struct` / `ai` 之一，由队长告诉你。

### ❌ 你绝对不能改的（**改了就是事故**）

| 文件 | 为什么 |
|---|---|
| `frontend/app.js` | 路由、菜单、外壳。**已做成自动发现** —— 你注册了路由，菜单自动亮，不需要你改 |
| `frontend/index.html` | 脚本加载顺序。加新文件由队长加一行 |
| `frontend/components.js` | 公共件，全平台共用。你要的东西没有 → **在 PR 里说明，让队长加** |
| `frontend/app.css` | 全平台样式 |
| `frontend/api-remote.js` / `mock.js` | API 门面 |
| `frontend/pages/<别人的板块>.js` | 别人的文件 |
| `backend/server.py` | 服务器主文件 |
| `scripts/acceptance.py` | 验收脚本。**已做成自动发现**，你加了页面它会自动认出来 |
| `data/` 下的参数库 | 参数带文献出处，改动要队长确认 |

**为什么这么严**：4 个 AI 同时改同一个文件 → 冲突必然发生，而且**没有人会解冲突**。
一人一个文件，物理上不可能撞车。

### 需要改公共文件怎么办

**不要自己改。** 在 PR 描述里写清楚：
> 「我需要 components.js 里加一个 XX 组件，用来做 YY」

队长会加，加完你再用。

## 3. 三条硬规矩（违反任何一条，PR 会被打回）

### 规矩 1：用现成的公共件，不要自己造

`components.js` 里已有（**先读开头注释块拿完整清单和用法**）：
`stat-card`（数值卡）、`trend-chart`（趋势图）、`event-list`（事件列表）、
`time-range`（时间窗）、`page-head`（页头）、`source-tag`（来源标签）、
`help-dot`（阈值依据问号）、`command-flow`、`heat-grid`。

**不允许**自己写一个长得差不多的卡片。全平台要长一个样。

### 规矩 2：数据一律走 API，**不许编**

```js
/* ✅ 对 */
const d = API.xxx();
return (d && d.items) || [];

/* ❌ 错 —— 写死数字 */
return [{ ts: Date.now(), value: 3.14 }];

/* ❌ 错 —— 直接读别的板块的全局变量 */
return window.SOME_OTHER_BOARD_DATA;
```

**数据拿不到就显示「—」或"暂无数据"，绝对不许编一个看起来合理的值。**

> 这不是洁癖。这个项目里每一个数字都要能回答"它哪来的"。
> 编一个数字，答辩时被问一句就塌。

### 规矩 3：界面上不许出现裸英文

```js
/* ❌ 错 */
'<td>{{ row.quality }}</td>'          // 会显示 "good"

/* ✅ 对 —— 用 components.js 里集中定义的 CN 映射表 */
'<td>{{ CN.quality[row.quality] }}</td>'   // 显示 "正常"
```

枚举字段（`quality` / `source` / `risk_level` / `alarm_status` …）**一律经 CN 表转中文**。
验收第 6 条专门查这个，还有自测。

## 4. 完成标准（Definition of Done）

**四条全过才算做完。少一条 PR 会被打回。**

| # | 标准 | 怎么验 |
|---|---|---|
| 1 | **验收脚本 8 项全过** | 双击 `验收检查.bat` |
| 2 | **浏览器 Console 里 Errors = 0** | 打开你的页面按 F12 → Console |
| 3 | **页面自检 6 条** | 见下 |
| 4 | **时间窗切换、按钮都点过一遍有反应** | 手动点 |

### 🔴 第 2 条为什么特别重要

**Vue 会把计算属性里的报错吞掉。** 后果是：

> 页面**看着完全正常**，但某个列表**永远是空的** ——
> 验收脚本查不出来，只有浏览器控制台能看到。

**我们已经被这个坑绊过一次**：海况页的"海况事件"列表恒为空，
页面照常渲染、8 项验收全过，直到有人在控制台看到 `ReferenceError` 才发现。

**所以：打开页面 → F12 → Console → Errors 必须是 0。**

### 页面自检 6 条（前端骨架规范 第六节）

```
☑ 用四个模板之一，不另起布局
☑ 页面顶部有数据来源标签（<page-head :sources="[...]">）
☑ 每个数值带单位与来源
☑ 数据缺失显示「—」而不是白屏
☑ 时间窗切换后所有图表一起刷
☑ 不直接读别人板块的数据（一律走 API）
```

## 6. 🔴 已知的坑（我们踩过的，你别再踩）

### 坑 1：computed 不读 `tick` → 数据回来也不重算

```js
/* ❌ 数据是异步拉的，这个 computed 会被永久缓存，页面永远是空的 */
rows: function () { return API.xxx().items; }

/* ✅ 读一次 tick，数据更新时才会重算 */
rows: function () { this.tick; return API.xxx().items; }
```

配套：`mounted` 里 `API.subscribe(...)`，`beforeUnmount` 里取消订阅。

**这个坑队长踩过三次。**

### 坑 2：template 是字符串数组，漏一个标点整个前端白屏

```js
template: [
  '<div>',
  '  <div class="card">',     // ← 行尾逗号不能漏
  '    <b>文字</b>',          // ← 字符串里的单引号要写成 \'
  '  </div>',
  '</div>'
].join('\n')
```

**你一个标点写错，会把全部 17 个页面一起弄白屏**（队长刚踩过：漏一个 `',`，
整个平台打不开，只能靠 `node --check` 定位到第几行）。

**所以提交前一定要跑 `验收检查.bat`。**

### 坑 3：Vue 吞掉计算属性里的异常（见第 4 节第 2 条）

### 坑 4：改了阈值/参数，忘了改仿真数据

如果新阈值让某个判断永远触发不到（或天天误报），**页面看着没错，但功能是死的。**

⚠️ 这个项目有一条设计原则：**该静默时静默，该报警时报警。**
设定阈值后，请确认：
- **平常情况不越线**（否则黄色预警天天响 = 没有预警）
- **异常情况能越线**（否则功能触发不了）

### 坑 5：写死阈值

水温告警线**按养殖鱼种自动取值**（见 `data/鱼种温度参数.json` 和 `data/farm.json`）。
**不要写死 20.5℃ 这类数字** —— 这是上一版犯过的错，导致大黄鱼在长得最好的时候被报警。

## 7. 这个项目的三条价值观（你的产出要符合）

| # | 价值观 | 具体表现 |
|---|---|---|
| 1 | **不编数据** | 拿不到就显示「—」。**宁可空着，不给假值** |
| 2 | **每条数据可追溯** | 每个数字都要能回答"哪来的"。参数带文献出处，实测带时间戳 |
| 3 | **离线可用** | 现场不能赌网络。联网只能是**显式动作**，页面渲染永远读本地 |

> 第 3 条尤其注意：**平台要在拔掉网线的状态下正常演示。**
> 如果你的页面需要联网才能显示，那就是错的。
