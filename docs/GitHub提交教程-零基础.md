# GitHub 提交产出教程（零基础版）

> 面向**从没用过 GitHub** 的人。全程不需要你写代码、不需要你懂命令行。
> 队长：刘桐麟　2026-10-06

---

## 一、先搞清楚三件事

### 1. GitHub 是什么

**全组共用的一个代码仓库**，放在网上。地址是：

```
https://github.com/tnightzz/deepsea-platform
```

谁能看、谁能改，由权限控制。

### 2. 为什么不能直接改，要先「Fork」

如果四个人都直接在公共仓库里改，**会互相覆盖对方的改动**，而且没人会修复。

所以流程是：**你先复制一份到自己名下，改你自己的那份，改好了再申请并入公共仓库。**

### 3. 三个词的意思（**记住这个比方就够了**）

| 词 | 意思 | 打比方 |
|---|---|---|
| **仓库** | 全组的代码放在网上的那个地方 | **全组的作文本** |
| **Fork** | 复制一份到你自己账号下 | 你**抄一份带回家**改 |
| **Pull Request（PR）** | 改完了申请并入公共仓库 | 你把改好的交给组长**审** |

**完整流程：**

```
① Fork        → 你账号下多一份一模一样的代码（改坏了也不影响别人）
② 改文件      → 你的 AI 干这活
③ Push        → 把你的改动传到你账号下那份仓库
④ 发 PR       → 告诉队长"我改好了，你看看要不要收"
⑤ 队长审      → 跑一遍验收，过了就合并
```

## 二、准备工作（**只做一次**）

### 第一步：注册 GitHub 账号

1. 打开 https://github.com/signup
2. 填邮箱 → 设密码 → 起用户名 → 验证邮箱
3. **把用户名告诉队长**（他要用它确认你的 PR）

> 用户名建议用真名拼音，比如 `wanghaoran` —— 方便队长认人。

### 第二步：⚠️ 解决网络问题（**国内大概率会卡在这一步**）

国内直连 GitHub 经常失败。**先测一下**：浏览器能不能打开
https://github.com/tnightzz/deepsea-platform

| 情况 | 怎么办 |
|---|---|
| 能正常打开 | ✅ 跳过这步 |
| 转圈打不开 / 很慢 | 需要开代理（VPN / 加速器）。**问队长要** |

> **队长这边实测踩过这个坑**：代理没开的时候，`git push` 会报
> ```
> Failed to connect to github.com port 443
> ```
> **看到这个报错，99% 是代理没开**，不是代码的问题。

## 三、正式流程（每次提交产出都走一遍）

### 第 ① 步：点 Fork

1. 浏览器打开 `https://github.com/tnightzz/deepsea-platform`
2. 看**页面右上角**，找到 **`Fork`** 按钮（在 `Star`、`Watch` 旁边）
3. 点它 → 下一页点绿色的 **`Create fork`**
4. 等几秒，页面会自动跳到 **`https://github.com/你的用户名/deepsea-platform`**

> **怎么确认成功了**：看页面左上角的仓库名，应该是 **`你的用户名/deepsea-platform`**，
> 下面有一行小字 `forked from tnightzz/deepsea-platform`。

### 第 ② 步：把下面这段话发给你的 AI

**直接复制，把方括号里的换成你的信息：**

```
请帮我完成一次 GitHub 提交。我不懂编程，请一步一步带着我做。

【背景】
我要往一个学生竞赛项目提交我负责的页面。
先读这份指南，按它做：仓库里的《AI协作指南.md》（队长会另外发给你）

【我的信息】
- 我的 GitHub 用户名：[填你的用户名]
- 我负责的板块：[fish / env / struct / ai 之一]
- 我要做的页面路由：[比如 /fish/growth]

【要做的事】
1. 克隆我 fork 的那份仓库：
   https://github.com/[你的用户名]/deepsea-platform
2. 先读完《AI协作指南.md》第 1 节列的 6 个文件，再动手
3. 只改 frontend/pages/[你的板块].js 这一个文件
   （需要新接口的话，改 backend/api/[你的板块].py）
   ⚠️ 不要碰任何其他文件
4. 改完必须做：
   - 跑 scripts/acceptance.py，8 项要全过
   - 用浏览器打开页面，按 F12 看 Console，Errors 必须是 0
5. 提交并推送到我 fork 的那份仓库
6. 告诉我下一步该点哪里

【要求】
- 每一步都告诉我"现在该我做什么"，不要一次说完
- 我不懂命令行，需要我操作的地方请说清楚点哪个按钮
```

### 第 ③ 步：等 AI 干完，它会告诉你

AI 会：
- 把仓库下载到本地（叫 `clone`）
- 改你那个文件
- 跑验收
- 把改动传上去（叫 `commit` + `push`）

**你不需要看懂它在做什么。** 但有两件事必须确认：

| 确认什么 | 怎么确认 |
|---|---|
| **验收 8 项全过** | AI 会贴结果给你，**看到 `8 / 8 通过` 才行** |
| **Console 没有报错** | AI 会贴结果，**看到 `Errors: 0` 才行** |

> ⚠️ **这两条不过，千万不要往下走。**
> 你一个标点写错，会把**全部 17 个页面一起弄白屏**。

### 第 ④ 步：发 PR（Pull Request）

**推上去之后，AI 会给你一个链接**，长得像：

```
https://github.com/tnightzz/deepsea-platform/compare/main...你的用户名:main
```

**点开它**，然后：

1. 页面上有个绿色的按钮 **`Create pull request`** → 点
2. 填标题，比如：`[鱼类] 完成生长模型与预测页`
3. 填描述（**照下面这个格式写**）：

```
## 我做了什么
- 完成页面：/fish/growth（生长模型与预测）
- 新增接口：无 / 或写清楚加了什么

## 验收结果
- 验收脚本：8 / 8 通过
- 浏览器 Console：Errors 0

## 需要队长配合什么
- 请在 frontend/index.html 加一行 <script src="pages/fish.js"></script>
  （如果这个文件还没被加载的话）
- 其他：无
```

4. 再点一次 **`Create pull request`** → **完成！**

### 第 ⑤ 步：等队长审

队长会：
- 看一眼你改了什么
- 跑一遍验收
- **过了** → 点合并，你的产出就进正式版本了
- **没过** → 会在 PR 下面留言，你照着改，改完再推一次（**不用重新发 PR**）

## 四、常见问题

### Q1：找不到 `Fork` 按钮

**位置**：仓库页面**右上角**，和 `Star`（星星图标）、`Watch`（眼睛图标）排在一起。
如果窗口太窄，可能被折叠进 `···` 里。

> 还没登录的话看不到，**先登录**。

### Q2：`git push` 报 `Failed to connect to github.com port 443`

**代理没开。** 这不是代码问题。

1. 打开你的代理软件（v2rayN / Clash 等）
2. 确认它**正在运行**
3. 再让 AI 重试一次

### Q3：`git push` 报 `Permission denied` 或要输密码

GitHub 现在不能用账号密码推送，需要 **Personal Access Token**。

**把报错原文发给你的 AI，让它带你生成一个**（在 GitHub 网页上：
右上角头像 → `Settings` → 左下角 `Developer settings` → `Personal access tokens`
→ `Tokens (classic)` → `Generate new token`）。

> 更省事的办法：装 **GitHub Desktop**（https://desktop.github.com/ ），
> 用它登录一次就不用管 token 了。让 AI 帮你切过去也行。

### Q4：我改错了文件，或者改坏了

**没事。** 你改的是**你自己那份**，公共仓库一点影响都没有。

让 AI 执行「撤销改动」，或者说「重新来一遍」，重新 clone 一份干净的就行。

### Q5：PR 发出去之后发现还有问题

**不用重新发 PR。** 直接在本地改了再 push 一次，
**PR 会自动更新**（因为你推的是同一个分支）。

### Q6：验收过不了，AI 也修不好

**别硬撑。** 把报错原文截图发群里。

> **卡住超过 20 分钟就发群里问。** 自己折腾的成本比问一句高得多。

### Q7：我真的搞不定 git

**备选方案**：在 GitHub 网页上直接改文件。

1. 打开你 fork 的那份仓库
2. 进入 `frontend/pages/`，点你那个文件
3. 点右上角的**铅笔图标** ✏️
4. 在网页上编辑（可以让 AI 给你完整代码，你整段粘贴进去）
5. 拉到页面最下面，填一句说明，点 **`Commit changes`**

> 这个办法**不适合改大文件**（几百行的代码在网页里编辑很难受），
> 但**应急能用**。

### Q8：实在不行，能让队长帮我提交吗

**可以，但这是最后手段。**

把文件直接发群里，队长手动放进去。**代价是仓库历史里看不出是谁写的**
—— 而"谁做了什么"是答辩时能拿出来说的东西。**尽量自己走完流程。**

## 六、动手前的三条提醒

1. **只改你那个文件。** 公共文件（`app.js` / `index.html` / `components.js` / `app.css`）
   **碰都不要碰** —— 需要改就写在 PR 描述里让队长改。
2. **验收不过不要发 PR。** 你把别人的页面弄坏了，全组都要返工。
3. **卡住就发群里问，别自己猜。** 猜错了比不写更麻烦。
